# Contracts

Status: Phase 1 design, for review. Decisions `Dn` refer to [protocol.md](protocol.md) section 9.

## 1. Liquid swap output

The code is in [contracts/swapkey](../contracts/swapkey). It has been run on an Elements 23.3.4 regtest node and on public Liquid testnet
([confidential.md](confidential.md)). It is unaudited.

Nothing on-chain looks at the asset or amount. **Each party must unblind the coin and check it before acting on it.**

### Output

A taproot output, funded at a confidential address.

| Part | Value |
|---|---|
| Internal key | MuSig2 aggregate of the maker's and taker's per-swap keys, in that order. Nobody can spend it alone. |
| Script tree | One leaf: the Simplicity refund program. |
| Blinding key | Generated by the taker, sent in the encrypted accept. It reads the coin and can't spend it. |

The tap tweak comes from `rust-elements`, because Elements tags it `TapTweak/elements`. The musig2 crate's built-in taproot tweak uses
Bitcoin's tag, and gives a key no Liquid node accepts.

### Claim: the key path

Both parties sign one exact transaction with an adapter signature locked to the point `T`. Nobody can finish it without `t`. On-chain it
is one 65-byte witness item, with no script, hash or secret.

- **L→S:** the maker needs the signature before it locks, because it publishes only after the taker reveals on Solana.
- **S→L:** the taker publishes, and the maker reads `t` as the difference between the published and adapter signatures.

The signature commits to all the inputs, so a claim's fee coin is fixed in advance, and its fee can't be raised.

### Refund: the leaf

[contracts/swapkey/src/refund.simf](../contracts/swapkey/src/refund.simf), with `SENDER_PK` and `LOCK_HEIGHT` compiled in, so each swap has its
own CMR and address. It requires both of:

1. `check_lock_height(LOCK_HEIGHT)`.
2. BIP-340 signature by `SENDER_PK` over `sig_all_hash`.

The refund has no covenant, so any coin at the address, of any asset or amount, can be recovered by the sender. On-chain it reveals four
witness items, so a refund is recognisable.

**Refund transactions must set a non-final `nSequence`.** `tx_lock_height` returns 0 when all sequences are final, so
`check_lock_height` fails on a transaction that sets the lock time but leaves sequences at the maximum. Confirmed on a
node ("Assertion failed inside jet").

**Earliest refund.** With lock time `LOCK_HEIGHT`, the node accepts the refund once the tip reaches `LOCK_HEIGHT`, so it
mines in block `LOCK_HEIGHT + 1`. Confirmed on a node.

### Invariants

| # | Invariant | Checked by |
|---|---|---|
| L1 | Spending by the key path needs both parties. | `SwapOutput::new` compares the signing key with the output key |
| L2 | A party's share can only be used with `t`. | `verify_share`, `combine`, `tests/regtest.rs` |
| L3 | Anyone holding the adapter signature can read `t` from the published signature, and nobody else can. | `tests/regtest.rs` |
| L4 | A refund needs the funder's key and the lock height. | The leaf, on a node |
| L5 | A coin that isn't exactly the agreed asset and amount is never acted on. | **Off-chain only:** `exact_secret_coin`, in the signer and client |
| L6 | A range proof's asset label can't be believed unless it opens the output's asset commitment. | `rust-elements` `unblind`, and `shared/chain/tests/forged_asset.rs` |

## 2. Solana escrow (Anchor)

Anchor v1.2.2, legacy Token program only. The mint is a compile-time constant selected by a Cargo feature: the real
USDT mint for a mainnet build, a stand-in for devnet.

### Accounts

**`Escrow`**, PDA `["escrow", initiator, lock_point.x]`:

| Field | Type | Notes |
|---|---|---|
| `initiator` | Pubkey | Funded the lock: a wallet, or a maker vault PDA. |
| `recipient` | Pubkey | Receives the claim. |
| `refund_token` | Pubkey | The only token account a refund may pay: the wallet's canonical account, or the vault's own. |
| `rent_payer` | Pubkey | Receives the rent, and may close early: the wallet, or the vault's operator. |
| `amount` | u64 | Base units, greater than 0. |
| `lock_point` | [u8; 64] | The point `T`, as x then y. |
| `created_slot` | u64 | |
| `deadline_slot` | u64 | Claim closes and refund opens here. |
| `close_on_restart` | bool | True for short-leg locks. |
| `extended` | bool | `extend` has been used. |
| `state` | enum | `Open`, `Claimed`, `Refunded`. |
| `revealed` | [u8; 32] | `s = t·Gx mod n`. Set on claim. Zero otherwise. |
| `settled_slot` | u64 | Slot of claim or refund. |
| `bump` | u8 | |

**Vault token account**, PDA `["vault", escrow]`, owned by the escrow PDA. One per swap, so a freeze affects one swap.

The seeds include the initiator, so nobody can front-run a lock with the same point and occupy another party's PDA.

**The revealed value stays in the account after claim.** Reading the transaction instead would be fragile: a claim made
through CPI with deliberately noisy logs could hide it, and free RPCs drop history. A plain `getAccountInfo` on a PDA
the maker can derive always works, and only the rent payer can close the account early.

### Instructions

Time rule used below, with `can_claim` and `can_refund` always exact opposites:

```text
restarted  = close_on_restart && LastRestartSlot > created_slot
can_claim  = state == Open && slot < deadline_slot && !restarted
can_refund = state == Open && !can_claim
```

| Instruction | Signer | Checks | Effect |
|---|---|---|---|
| `lock(lock_point, recipient, amount, deadline_slot, close_on_restart)` | initiator | Mint matches. `amount > 0`. `deadline_slot > slot`. `recipient != initiator`. | Creates escrow and vault, moves `amount` in. |
| `claim(revealed)` | anyone | `can_claim`. `secp256k1_recover(0, 0, Gx, revealed) == lock_point`, which holds only for `revealed = t·Gx mod n`. Recipient token account is the canonical ATA for the mint and owned by `recipient`. | Moves funds to recipient, stores the value, sets `Claimed`, closes vault. |
| `refund` | anyone | `can_refund`. Destination is exactly `refund_token`, still owned by `initiator`. **An owner check alone is unsafe:** anyone can create a token account owned by a vault PDA, and a refund sent there would be stuck forever (found in review, covered by tests). | Moves funds to the initiator, sets `Refunded`, closes vault. |
| `extend(new_deadline)` | recipient | `state == Open`. `!close_on_restart`. `!extended`. `slot < deadline_slot`. `deadline_slot < new_deadline ≤ deadline_slot + MAX_EXTENSION` (3,000,000 slots, about 7 days). | Moves the deadline, sets `extended` (D1). |
| `release` | recipient | `state == Open` | Returns funds to the initiator at once, sets `Refunded`. For a maker who can't fill the swap. |
| `close` | rent payer any time, anyone after `RETENTION` (3,000,000 slots) | `state != Open` | Closes the escrow, rent goes to the rent payer. |

The claimer adds an idempotent ATA creation before `claim` when needed. A refund destination that doesn't exist or is
frozen makes the refund fail with no state change, so it can be retried. It never pays someone else.

### Invariants

| # | Invariant |
|---|---|
| S1 | Vault balance equals `amount` while `Open`, and the vault is gone afterwards. |
| S2 | Funds only ever leave to the recipient's canonical account or `refund_token`. |
| S3 | Claim requires the value that opens `lock_point`. |
| S4 | `can_claim` and `can_refund` are never both true, and for an `Open` escrow exactly one is. |
| S5 | `state` moves from `Open` to `Claimed` or `Refunded` and never changes again. |
| S6 | Once `Claimed`, the revealed value stays readable until `close`, and only the rent payer can close before `RETENTION`. |
| S7 | The deadline moves only through `extend`: once, later only, by the recipient, on a long-leg escrow, and capped. |
| S8 | Only the configured mint and the legacy Token program are accepted. Token-2022 is rejected. |
| S9 | The program holds no global authority, admin key or fee switch. |

### Compute and rent

A claim measures 40,916 CU in LiteSVM, well under the 200,000 default. The binary is 334 KB. Trailing bytes after a
32-byte value are ignored by Anchor, and they aren't stored. Rent for the escrow and vault is returned at settlement or `close`.

### Modules beyond the core

These live behind separate instructions so the core stays auditable. A maker can lock directly with `lock` and never use
the vault.

**Maker vault (D6, accepted: in scope).** PDA `["maker_vault", owner]`, with a token account.

| Instruction | Signer | Effect |
|---|---|---|
| `vault_init(operator, window_slots, window_cap)` | owner (cold) | Creates the vault |
| `vault_deposit(amount)` | anyone | Adds funds |
| `vault_withdraw(amount)` | owner | Withdraws, cold key only |
| `vault_set_operator(operator, window_slots, window_cap)` | owner | Rotates the hot key or changes the cap |
| `lock_from_vault(...)` | operator | As `lock`, with `initiator` = the vault PDA, limited to `window_cap` per `window_slots`. Funds from refund return to the vault. |

The operator can't withdraw, but it can lock vault funds to a recipient it controls and claim them, so **the cap, not
the key separation, limits a stolen hot key.** A vault is one freezable token account, unlike per-swap vaults, so the
maker should keep its balance near operating needs.

**L→S taker bond (D2: not in v1, kept here as a design for later).** Lamports in PDA `["bond", taker, lock_point.x]`.

| Instruction | Signer | Effect |
|---|---|---|
| `post_bond(lock_point, maker, lamports, expiry_slot)` | taker | Creates the bond |
| `lock_bonded(...)` | maker | As `lock`, and binds the bond |
| `reclaim_bond` | anyone | Returns an unbound bond after expiry |

On a bound escrow: `claim` returns the bond to the taker. `refund` pays it to the maker, unless `restarted` is true, in
which case it returns to the taker, since a chain restart isn't the taker's fault.

## 3. Shared test vectors

`contracts/swapkey/tests/values.rs` computes the point, the revealed value and the secret from the curve's definition, separately from the code
under test, and the program's tests in `programs/solana-escrow/tests/escrow.rs` use the same values. A wrong sign, an out-of-range value and the
other `y` for the same `x` must all be refused.
